- ทำซ้ำข้อผิดพลาดจากภาพได้: `GET /` ที่ localhost ตอบ 200 แต่ใส่ Host `nearby-awning-outing.ngrok-free.dev` ตอบ 403 พร้อมข้อความ `Blocked request`
- เพิ่ม `--preview` และ launcher `pnpm preview:tunnel <https-origin>`; บน Windows ใช้ `start-demo.ps1 -PreviewOrigin <https-origin>` ซึ่ง build ให้ก่อน
- โหมดพรีวิวใช้ static build และฐานข้อมูลแยก มีรหัสผ่านสุ่มก่อนเข้าเว็บ; ไม่เปิด Vite source server หรือยกเลิกกฎ Origin ของ dev ปกติ
- Integration test ผ่าน HTTP จริง: Host แบบ ngrok เห็นหน้ารหัสผ่าน, ใส่รหัสถูกแล้วได้หน้า built app, ล็อกอินชื่อทดลองและรับ snapshot/ส่งแชตผ่าน WebSocket ได้
- ตรวจการปฏิเสธรหัสผิด, Origin อื่น, cookie ปลอม, API และ WebSocket ที่ไม่มี cookie พรีวิว; cookie ใช้ HttpOnly/Secure และ redirect ไม่ออกนอกเว็บไซต์
- `pnpm build` ผ่าน; `pnpm test` ผ่าน 38 tests; `pnpm check:production` ผ่าน และ production ยังปิด demo sign-in
- ยังไม่ได้ยืนยันผ่าน ngrok tunnel ของผู้ใช้จริง เพราะไม่พบ ngrok agent ที่ localhost:4040 ใน workspace host นี้ ผู้ใช้ต้องหยุด dev server และเริ่ม protected preview ตาม README ก่อน
- การ forward พอร์ตเว็บไม่ทดแทนการตั้งเครือข่าย LiveKit สำหรับเสียง วิดีโอ และแชร์หน้าจอจากเครื่องอื่น

## ปรับ UI ให้เรียบแบบ ZEP

- แผนที่ใช้พื้นที่หลักเต็มหน้าต่าง ย้ายรายชื่อและห้องประชุมเป็นการ์ดลอยที่เปิด–ปิดได้
- เปลี่ยนเมนูซ้ายเป็นพื้นสว่าง ใช้สีม่วงกับปุ่มหลัก และรวมสถานะ/สื่อ/รีแอ็กชันไว้ในแถบลอยด้านล่าง
- ตัดหัวข้อและข้อความตกแต่งขนาดใหญ่ เพิ่มปุ่มที่นั่งและจำนวนออนไลน์แบบย่อ
- แชตกับรายละเอียดห้องสลับกันเปิด เพื่อลดแผงทับกัน; หน้าเข้าสู่ระบบเป็นการ์ดกลางหน้าจอ
- TypeScript และ production build ผ่าน ตรวจ browser ที่ 1280×720 และ 706×884 โดยใช้ฐานข้อมูล `data/clean-ui-qa.sqlite` แยกจากเดโมหลัก
- Browser: เปิด/ปิดรายชื่อ เปิดเมนูห้อง เข้าห้อง Bloom และส่งแชตสำเร็จ; กดขวา 25 ms จาก (684,444) จบที่ (708,444) ยังคงเดินครั้งละหนึ่งช่อง
- ซ่อนแผนที่ตกแต่งหน้าเข้าสู่ระบบจาก keyboard และ accessibility tree พร้อมชื่อปุ่มที่นั่งเมื่อแสดงเฉพาะไอคอน

## ปรับการเดินแบบกริด

- ใช้กริด 24 พิกเซลและการเดินสี่ทิศร่วมกันทั้งคีย์บอร์ด การคลิก เส้นทาง ที่นั่ง และจุดเข้าห้อง
- เซิร์ฟเวอร์เก็บตำแหน่งกลางช่อง พร้อมช่วงการเคลื่อนระหว่างช่อง; ฝั่งแสดงผลวาดต่อเนื่องตามจังหวะหน้าจอและช่วงก้าวจริง จึงไม่ตัดมุมเป็นเส้นทแยง
- เพิ่มกรณีทดสอบกดสั้นระหว่าง tick, เปลี่ยนทิศกลางช่อง, ชนผนัง, input หมดอายุ, การแสดงผลเมื่อ packet มาหลังเริ่มเลี้ยว และแย่งช่องสุดท้ายของห้องประชุม
- ทดสอบ browser ด้วยฐานข้อมูล `data/grid-qa.sqlite` แยกที่พอร์ต 4175 เพราะเดโมเดิมใช้พอร์ต 4173 อยู่
- Browser: กดขวา 25 ms จาก (684,468) แล้วหยุดที่ (708,468); ไปที่นั่ง (588,204) และกดขึ้นค้างแล้วหยุดก่อนโต๊ะที่ (588,180)
- Browser: คลิกพิกัดพื้นภายในช่องแล้วจบที่ (828,468); ระหว่างก้าวอ่านตำแหน่งภาพได้ประมาณ (712.338,468) ขณะที่ตำแหน่งหลักเป็น (708,468) ยืนยันการแสดงผลระหว่างกลางช่อง
- เพิ่มปุ่มแสดงกริดช่องเดินและรวมพิกัดเฟอร์นิเจอร์ที่วาดกับพิกัดชน รวมทั้งกระถางทางเดินที่เดิมไม่มีตัวบล็อก

ต้องรีสตาร์ตเซิร์ฟเวอร์เดโมเดิมหนึ่งครั้งเพื่อโหลดกฎการเดินใหม่

## ผ่าน

- `pnpm build`: TypeScript ผ่านและสร้าง production assets สำเร็จ
- `pnpm test`: ผ่าน 24 tests รวม HTTP/WebSocket จริงกับฐานข้อมูลแยกสำหรับทดสอบ
- HTTP: cookies, session signature, Origin validation, สิทธิ์ admin และการถอนสิทธิ์ที่ยกเลิก WebSocket
- Domain: จุดเกิดและเส้นทางไปโต๊ะ/ห้อง, ชนผนัง, ความเร็วแนวทแยง, click-to-walk เข้าห้องผ่านกฎ server, จำนวนผู้เข้า, การแยกแชต, ที่นั่งไม่ซ้ำ, อายุข้อมูล และอายุคำเชิญ
- Guest: อ่านแชตส่วนกลาง/ห้องอื่นไม่ได้ ย้ายออกจากห้องที่เชิญไม่ได้ เปลี่ยนสถานะ/จองที่นั่งไม่ได้ และเซสชันถูกยกเลิกเมื่อถอนคำเชิญหรือถอนสิทธิ์ผู้เชิญ
- Browser QA: ใช้สองเซสชันผ่าน localhost และ 127.0.0.1 เห็นผู้ใช้สองคน เปลี่ยนสถานะ จองที่นั่ง กลับที่นั่ง ส่งข้อความ และตรวจข้อความปรากฏอีกเซสชัน
- Browser QA: เปิดห้อง Bloom เห็นจำนวนผู้เข้าห้องและสถานะบริการประชุมที่ยังไม่เชื่อม
- ตรวจ desktop 1280×720 และหน้าต่างแคบประมาณ 706×884; เพิ่ม drawer ให้เปิดรายชื่อและห้องได้ในหน้าต่างแคบ
- โต๊ะใน SVG เลือกผ่านปุ่มที่มีชื่อใน accessibility tree ได้
- `start-demo.ps1`: parse ผ่านและทดลองเปิดเซิร์ฟเวอร์จริงที่ localhost:4173 สำเร็จ

## ต้องตรวจเมื่อเชื่อมองค์กรจริง

- Google/Microsoft OIDC: ต้องมี client credentials และ redirect URI ขององค์กร
- LiveKit: ต้องมี endpoint และ server credentials เพื่อทดสอบเสียง กล้อง แชร์หน้าจอ การ reconnect และการตัดสื่อเมื่อถอนสิทธิ์จริง
- จำนวนผู้ใช้พร้อมกัน 20 คนและวิดีโอห้องละ 8 คนยังไม่ได้ทดสอบโหลดกับบริการสื่อจริง
- Dockerfile มีไว้เตรียมย้ายระบบ ยังไม่ได้ build/run Docker ในสภาพแวดล้อมนี้
- ค่าใช้จ่าย ที่ตั้งข้อมูล HTTPS reverse proxy และนโยบาย IT ต้องยืนยันก่อนเปิด pilot บนเครือข่ายองค์กร
